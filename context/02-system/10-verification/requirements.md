# Verification — Requirements

## Context

Owns how Cloudstash proves pure logic, workspace data semantics, Cloudflare
runtime behavior, and protocol compatibility. Delivery owns build, CI, and
release provenance.

## Assumptions

- **CS.SYS.VER-A01 Local Worker fidelity is useful but incomplete:** The
  Cloudflare Vitest pool can reproduce persistence and forced DO eviction, but
  production billing, placement, and all timing still need deployed evidence.
  - Validation: sync/eviction E2E results and operations incidents.

## Constraints

- **CS.SYS.VER-C01 Determinism:** Tests must avoid live provider/network timing
  unless the lane explicitly owns an external integration check.
- **CS.SYS.VER-C02 CI cost:** Fast deterministic unit/data/Intent checks run by
  default; expensive remote checks remain explicit.

## Acceptable Tradeoffs

- **CS.SYS.VER-T01 Multiple lanes:** Standard Vitest, Workers-pool Vitest,
  extension Bun tests, build assertions, and external checks remain separate
  because no one runtime represents all boundaries.
- **CS.SYS.VER-T02 Real data layer:** Data tests use an in-memory LiveStore
  rather than mocking commits/queries, accepting SQLite/WASM test overhead.

## Requirements

- **CS.SYS.VER-R01 Pure unit lane:** Domain logic, decoders, errors, services,
  handlers, and UI utilities must run without remote infrastructure.
- **CS.SYS.VER-R02 Real materialization:** Event and query tests must commit to a
  real isolated in-memory store and shut it down after each test.
- **CS.SYS.VER-R03 Flow coverage:** Link ingestion, tagging, reprocess, event
  migration, and deletion cascades must be tested as event→materialized-state
  flows. `refines: CS.SYS.DATA-R03`
- **CS.SYS.VER-R04 Worker E2E:** Auth, APIs, D1 migrations, queues, Workflows,
  and Durable Object RPC/storage behavior use the Cloudflare Workers pool.
- **CS.SYS.VER-R05 Forced eviction:** Eviction-sensitive behavior uses
  `abortAllDurableObjects()`, reacquires fresh stubs, and verifies persisted
  truth rather than stale client memory.
- **CS.SYS.VER-R06 Sync arrival:** Tests inspect SyncBackendDO eventlog progress
  for single, concurrent, queue, and cold-recovery flows. `refines: CS.SYS.SYNC-R09`
- **CS.SYS.VER-R07 Wire compatibility:** Golden events generated by prior
  runtime versions must remain byte-decodable and semantically stable.
- **CS.SYS.VER-R08 Entitlement matrix:** Complete tier capability defaults and
  server gates must have regression coverage.
- **CS.SYS.VER-R09 Authorization parity:** Primary sync/API/stateful boundaries
  and their preflight/UI helpers must share or prove equivalent approval,
  membership, workspace, and capability decisions.
- **CS.SYS.VER-R10 Multi-store deletion:** Deletion tests seed every selectively
  purgeable owner, inject target failures, and prove no retained source/intake
  can recreate state after completion.
- **CS.SYS.VER-R11 No false green:** A check over an absent corpus, empty test
  selection, skipped target scenario, ignored package failure, or assertion that
  accepts any non-target error status cannot count as verification evidence.
